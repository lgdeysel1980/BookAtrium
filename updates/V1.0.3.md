# BookAtrium v1.0.3

Version: 1.0.3

## What's New

### Standalone eBook Reader

The built-in eBook reader has been moved into its own standalone application:

- Added `eBookReader.exe`.
- Opening an ebook now launches the dedicated reader process.
- The reader remains open if the main BookAtrium application is closed.
- Existing reading state, bookmarks, positions, annotations, and other database-backed reader functionality remain integrated with the BookAtrium library.
- Added a dedicated eBookReader application and taskbar icon.

### Standalone Audiobook Player

The audiobook player has also been moved into its own standalone application:

- Added `AudioPlayer.exe`.
- Audiobooks now open in an independent player process.
- Audio playback can continue after the main BookAtrium application is closed.
- Existing audiobook chapter support remains available.
- Playback positions and audiobook metadata continue to integrate with the existing BookAtrium library.
- Added a dedicated AudioPlayer application and taskbar icon.
- Improved standalone audiobook metadata loading and database fallback behavior.
- Fixed audiobook covers not appearing when cover artwork was stored in the BookAtrium database.
- Improved SQLite GUID handling when loading audiobook format information.

## User Interface Improvements

### Book Details

- Reduced the size of the cover displayed in the Book Details pane.
- Cover sizing is now responsive rather than using the previous large fixed width.
- Author names are now displayed naturally as a comma-separated inline list.
- Each author remains individually clickable.
- Long author lists wrap correctly without leaving a trailing comma.

### Database Selection

- Added a close **X** to the top-right corner of the Database Selection screen.
- The original splash-style appearance has been preserved.
- Closing the Database Selection screen now exits BookAtrium cleanly without requiring a database to be selected or created.
- Cancelling database selection is treated as a normal application exit rather than an error.

## Startup & Troubleshooting

Added new command-line troubleshooting options for BookAtrium:

- `--debug` — enables additional startup and environment diagnostics.
- `--verbose` — enables more detailed application logging.
- `--safe-mode` — starts BookAtrium without loading community/third-party plugins while keeping official BookAtrium plugins available.
- `--log-file <path>` — writes diagnostics to a specified log file.

Debug diagnostics can include information such as:

- BookAtrium version.
- .NET runtime version.
- Windows version.
- Process architecture.
- Application directory.
- Database startup status.
- Plugin discovery.
- Main window initialization.
- Application shutdown stages.

Safe Mode affects only the current BookAtrium session and does not permanently disable or modify installed plugins.

## Microsoft Store Preparation

BookAtrium's previous built-in application update system has been removed in preparation for Microsoft Store distribution.

Changes include:

- Removed the **Check for Update** button from the main BookAtrium window.
- Removed automatic application update checks during startup.
- Removed the legacy BookAtrium updater service and updater executable integration.
- Removed the obsolete **Autocheck for updates** preference.
- Microsoft Store/MSIX will now be responsible for application updates.

This change affects only BookAtrium application updates. Community plugin update functionality remains available.

## Fixes & Reliability

- Fixed standalone reader/player resource loading issues.
- Fixed Syncfusion licensing initialization in the standalone applications.
- Fixed embedded icon and font resource loading in the standalone applications.
- Fixed audiobook database cover retrieval and handoff to the standalone player.
- Fixed SQLite text-stored GUID values causing format-loading failures.
- Improved resilience so optional audiobook metadata failures no longer discard successfully loaded cover information.
- Aligned BookAtrium, AudioPlayer, and eBookReader with the x64 desktop architecture.
- Removed temporary development resource-probe infrastructure from the solution.
- Improved companion database access while ensuring the main BookAtrium process remains the sole owner of the library instance lock.

## Notes

- BookAtrium, AudioPlayer, and eBookReader now run as distinct Windows applications with their own taskbar identities.
- Closing BookAtrium does not automatically close an active eBookReader or AudioPlayer.
- No database schema migration is required specifically for the standalone reader/player changes.
- Existing official plugin, community plugin, web server, ebook, audiobook, and library functionality remains compatible with this release.
